## 1. 目标

将任务、原文、证据、核验和报告保存为可恢复、可追溯的持久对象。

先阅读 [统一约定](./COMMON.md)、[执行总览](./README.md) 和 [PRD](../market-insight-agent-prd.md) §7.8、§8、§9.1、§10。工单中的文件范围相对于仓库根目录；新增路径尚待实现。前置产物须已合入当前执行分支，不能另造占位依赖后宣称完成。

## 2. 当前代码入口

- [当前报告持久化](../../../backend/server/report_store.py)
- [已有 API](../../../backend/server/app.py)

这些文件是阅读与复用入口，不表示都必须修改。优先在本单责任范围实现，通过契约接入现有模块。

## 3. 输入与交付物

**输入**

- MI-002 的对象和 Repository 端口；首期默认单节点。

**交付物**

- Repository 实现、版本化迁移、受控原文存储、审计及事务接口。

## 4. 实现范围

1. 按 Repository 端口实现 SQLite 单节点默认后端；若当前项目已明确采用 PostgreSQL 则复用，保持后端可替换，不同时开发两套生产后端。
2. 实现任务/阶段检查点、文档版本/片段、主张及关系、核验、派生分析、报告版本、事件与审计的持久化及必要查询。
3. 保存原始字节或授权片段，记录哈希、存储形式、获取时间与解析版本；同 URL 内容变化生成新版本。
4. 为重试和并发插入实现稳定幂等键/唯一约束；将已验证报告与冻结证据集在事务内关联。
5. 提供按工作空间过滤的查询、失效标记、引用保护的清理接口、备份恢复步骤；文件不放入公开 outputs 静态目录。
6. 提供后续核验/复核/报告需要的事务和乐观并发接口，避免各模块绕过存储层直接修改 JSON。

## 5. 文件责任范围

## 6. 验收条件

- [ ] 重启进程后任务、原文定位和报告证据链仍可读取；重复提交同一阶段结果不新增重复记录。
- [ ] 旧报告保持旧版本；更新原文/主张不会无痕覆盖已发布快照。
- [ ] 工作空间过滤在查询中生效，非法跨空间引用被拒绝；API 级鉴权由 MI-004 补齐。
- [ ] 不存在“数据库写入成功但正式报告引用的材料未保存”这一成功状态；部分失败可重试或明确失败。
- [ ] 能从备份恢复一个含原文、核验和报告关系的示例。

## 7. 验证与交接

- 运行 SQLite 事务、重启重读、幂等写入、版本替代、跨空间引用和备份恢复行为测试。

按 [统一交接模板](./COMMON.md) 报告实际运行命令、结果、未测项、接口变化和集成说明。组件尚未挂入主应用时，明确 `ready_for_integration` 及接入工单，不将模拟结果冒充真实端到端能力。

## 8. 本单边界

不迁移旧报告为已核验报告，不替代旧 reports.json 的所有普通报告功能。
