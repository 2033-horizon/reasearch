# 证据持久化：SQLite 作为证据系统之记录，报告存储本期不动

- 状态：accepted
- 日期：2026-09-29

## 决策

阶段二起，来源档案、证据条目、证据组、裁决结论、复核记录与调研运行写入单一 SQLite 数据库（证据系统之记录）；JSON + Markdown 证据产物保留为可下载快照（由库导出）。后端既有 `reports.json`（ReportStore）本期不迁移。跨调研复用本期只做抽取缓存（同 URL + 原文引用不重抽），已裁决结论跨调研复用（含"该指标已有 A 级数据"）推迟到后续阶段。

## 原因

裁决、复核与审计需要按证据组、来源、状态做跨记录查询与更新，JSON 文件与内存列表无法可靠支撑；SQLite 零运维、单文件、可随容器部署。报告存储在功能上独立于证据库，本期不扩大改动面。

## 考虑过的方案

- **继续 JSON/内存**：查询与并发更新困难，复核状态无处可靠落盘。
- **直接上 Postgres**：部署与运维成本超出内网工具需要。

## 后果

- 需要 schema 版本管理与轻量迁移约定（使用 `pragma user_version`）。
- 证据库与报告文件各走各的存储，边界需在文档中说明。
