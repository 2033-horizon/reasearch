## 1. 目标

提供新的市场洞察入口，创建任务时即绑定身份、范围与预算，并保护后续所有证据资源。

先阅读 [统一约定](./COMMON.md)、[执行总览](./README.md) 和 [PRD](../market-insight-agent-prd.md) §4、§7.2、§9.3、§10。工单中的文件范围相对于仓库根目录；新增路径尚待实现。前置产物须已合入当前执行分支，不能另造占位依赖后宣称完成。

## 4. 实现范围

1. 新增 /api/insight 前缀，创建任务保存对象、别名、目的、区域/期间/截止日、必答指标、假设、语言和预算；服务端生成 ID。
2. 识别缺失的必填范围与企业歧义，返回结构化需澄清字段或保留草稿，不默选同名公司。
3. 支持任务创建幂等、分页历史、单任务状态查询；前端传入 user_id/workspace_id 不得覆盖服务端授权上下文。
4. 抽象内部身份与 read/review/admin 权限；优先对接现有公司身份。尚无系统时提供服务端配置的试点凭据和关闭的默认访问策略，不能信任公网任意身份请求头。
5. 创建文档/证据/复核/报告/导出子路由的组合扩展点。共享 app.py 由本单注册一次，后续模块按集成工单统一挂载。
6. 提供跨工作空间拒绝访问测试和用于后续模块的同一鉴权依赖；避免把受限材料注册到公共静态路径。

## 6. 验收条件

- [ ] 重复幂等请求得到同一任务；不同任务的中文、范围、预算互不污染。
- [ ] 缺少身份不能获取任务，普通读取者不能复核或改规则；跨空间 ID 猜测被拒绝。
- [ ] 企业歧义明确出现在草稿/响应中，不进入已确定研究阶段。
- [ ] 历史以服务端为准；换浏览器可按权限获取任务，前端不必提交 localStorage IDs 才能发现历史。
- [ ] 普通研究入口仍可运行；新增模式清楚区分 draft/verified。

## 7. 验证与交接

- 运行 API 成功/错误、幂等、权限矩阵及跨空间访问用例；后续证据/导出路由须复用同一测试思路。

按 [统一交接模板](./COMMON.md) 报告实际运行命令、结果、未测项、接口变化和集成说明。组件尚未挂入主应用时，明确 `ready_for_integration` 及接入工单，不将模拟结果冒充真实端到端能力。
