# 证据裁决与证据驱动报告（阶段二）：聚类、裁决、例外复核、Word 脚注引用与 SQLite

Status: ready-for-agent

## Problem Statement

阶段一交付了可溯源、已按来源等级分级的证据表，但部门负责人的核验负担仍在：

1. **合并比对仍靠人工**：同一指标的数据散落在多条证据里（不同来源、不同写法、口径相近或不同），要人工判断哪些是同一个事实，哪些口径不同不能合并
2. **采纳门槛仍靠人工**：来源等级标注了，但"多少条独立来源才算数、转载算不算、同主体多域名算不算"仍要人工判断，低可信来源的交叉验证最费时间
3. **冲突数据靠人工裁定**：数值出现分歧时要人工找原因、判断信谁；判断不了只能搁置
4. **报告与证据仍是两张皮**：报告基于未验证的上下文写作，数据没有逐条引用，无法做到"每个数字都可一键追溯到网页原文"

负责人真正想要的：调研结束即得到一份"每个数字都经过核验、可逐条追溯"的报告，人工只处理少数例外项。

## Solution

在证据层之上增加"归一化聚类 → 规则化裁决 → 例外复核 → 证据驱动写作"四个环节：

- **聚类**：把同一指标（实体、指标、期间、地域、单位相同）且口径一致的跨来源证据条目归并为**证据组**；口径不同一律拆组
- **裁决**：按**裁决策略表**判定每个证据组——A/B 级来源单条即采纳（B 可配置）；C/D 级需 2/3 条**独立来源**（按发布主体去重，转载只计一条）；数值在容差内取**代表值**，超出容差按等级→时效裁定，无法裁定进入**待审**
- **复核**：独立复核页面只展示例外项（冲突待审、证据不足待审），人工做采纳/否决/指定主来源；复核后报告可重生成（旧版本保留）
- **证据驱动报告**：正文只使用**有效结论**（采纳、交叉验证通过）对应的证据；每个数据点带 [序号] 上标，Word 报告在当页底部显示"标题 — 发布主体（等级）· 日期 · URL"真脚注；待审数据默认列入报告附录
- **留存**：来源、证据、证据组、裁决、复核与运行历史全部落 SQLite；JSON + Markdown 证据产物继续可下载

## User Stories

1. 作为领导，我想要系统自动把同一指标的跨来源数据合并比对，这样我不再逐条人工比对同一数字的不同版本
2. 作为领导，我想要 A 级（政府及政府间组织）来源的数据单条即被采纳，这样最权威的数据不占用我的核验时间
3. 作为领导，我想要 B 级（权威机构与央媒）的采纳门槛可配置（默认单条采纳、可调为需佐证），这样信任尺度由业务决定而不是写死在系统里
4. 作为领导，我想要 C/D 级数据分别由 2/3 条独立来源支撑才被采纳，这样低可信来源也必须被交叉验证
5. 作为领导，我想要同一发布主体的多个域名与转载都不重复计数，这样"媒体互相转载"不会被误当成多方印证
6. 作为领导，我想要数值有细微差异（容差内）时视为一致并采用权威度最高的版本，差距过大时按等级与时效自动裁定、无法裁定则标记待审，这样矛盾数据不会被悄悄掩盖
7. 作为领导，我想要口径不同的数据永远不合并，这样"零售额"和"出货额"不会混成一个事实
8. 作为领导，我想要报告正文只出现已采纳与交叉验证通过的数据，这样我读到的每个数字都经过验证
9. 作为领导，我想要每个数据点带 [序号] 上标，并在 Word 中于当页底部看到"标题 — 发布主体（等级）· 日期 · URL"脚注，这样我随手就能核实来源
10. 作为领导，我想要 Word 报告打开即显示真脚注（Word 与 WPS 均可见、URL 可点击、导出 PDF 后保留），这样核验不需要另开系统
11. 作为领导，我想要未采信的数据（冲突/证据不足）默认列在报告附录（可关闭），这样我知道哪些数据被排除以及为什么
12. 作为领导，我想要复核完例外项后能重生成报告且旧版本保留，这样我拿到最终版且历史可回查
13. 作为领导，我想要复核只打扰我处理例外项、正常数据不需要我操心，这样核验从数小时缩短到几分钟
14. 作为领导，我想要复核页面里看到每个证据组的全部来源对比（等级/主体/数值/口径/引用/URL），这样我能快速做出采纳与否决的决定

15. 作为市场分析师，我想要证据组保留统计口径并在口径冲突时拆组，这样合并永远建立在同口径上
16. 作为市场分析师，我想要数值容差（默认 ±5%）与各级门槛在裁决策略表中维护，调整不需要改代码发版
17. 作为市场分析师，我想要文本型事实（并购、政策、事件）也走等级裁决——近义合并、语义冲突待审——这样非数字结论同样可信
18. 作为市场分析师，我想要每个证据组可查到裁决依据（命中规则、参与来源、转载归并、容差比较），这样结论可解释、可复盘
19. 作为市场分析师，我想要多条来源一致时报告采用代表值（等级最高且最新），这样同一指标在报告里只有一个口径一致的取值
20. 作为市场分析师，我想要调研过程中实时看到聚类与裁决进度（已归组、已裁决、待审数、各级统计），这样我知道任务进行到哪一步
21. 作为市场分析师，我想要在复核页面上对证据组做采纳/否决/指定主来源，处置后报告重生成即反映我的决定
22. 作为市场分析师，我想要同一 URL + 原文引用的证据复用缓存不重复抽取，这样重复调研省时省钱
23. 作为市场分析师，我想要证据产物（证据组 + 裁决结论 + 复核记录）仍可下载 JSON 与 Markdown，这样会上能直接引用与转发
24. 作为市场分析师，我想要报告里每个上标 [序号] 能对应到下载产物中的证据组/条目，这样抽查时可双向定位

25. 作为事后复核者，我想要每条裁决结论记录命中的规则与参与来源，这样任何结论都能独立复盘
26. 作为事后复核者，我想要复核动作记录复核人与时间，这样例外处置可追责
27. 作为事后复核者，我想要报告版本与生成时的证据库状态关联，这样旧版报告对应当时的裁决结果
28. 作为事后复核者，我想要被否决与待审的数据保留在库中不删除，这样历史完整、可重审

29. 作为开发者，我想要裁决管线由配置开关控制且默认关闭，这样未启用时现有行为零变化
30. 作为开发者，我想要证据库使用 SQLite 并带 schema 版本与轻量迁移约定，这样裁决、复核与审计有可靠存储且演进不丢历史
31. 作为开发者，我想要 DOCX 脚注由自研注入实现、不引入 pandoc 等外部工具，这样部署保持零新增系统依赖
32. 作为开发者，我想要聚类与归并的 LLM 判定结果落库并缓存，这样同一输入不重复消耗调用且判定可审计

## Implementation Decisions

### 模块与修改范围

- **算法模块扩展（evidence 模块）**：新增 聚类（证据组归并）、裁决（门槛/独立性/转载/容差/代表值/待审）、存储（SQLite）、产物 schema v2。公开入口维持"聚合后的来源列表 + 证据条目 → 证据产物（含证据组与裁决结论）"，LLM、策略表路径、DB 路径通过参数注入，便于测试
- **裁决策略表**：以 YAML 数据文件维护（随包发布，路径可覆盖），初版形状（契约）：

  ```yaml
  version: 1
  tiers:
    A: { min_independent_sources: 1 }
    B: { min_independent_sources: 1 }   # 可配置为 2
    C: { min_independent_sources: 2 }
    D: { min_independent_sources: 3 }
  value_tolerance:
    relative: 0.05
  resolution_order: [tier, recency]
  ```

- **聚类行为**：确定性键（实体、指标、期间、地域、单位）分块 → 块内经 LLM 结构化判定（指标同义归并、口径 same/compatible/different）→ different 一律拆组；判定结果落库、可缓存，含判定依据
- **独立性判定**：按发布主体去重（无 publisher 时退化按域名）；转载 = 有明确来源标注或原文引用高度相似；判定存疑按"不算独立"（保守）；每条归并记录依据（哪几条被视作转载、归到谁）
- **裁决结论（状态机）**：`accepted`（采纳）｜`cross_validated`（交叉验证通过）｜`conflict_pending`（冲突待审）｜`insufficient_pending`（证据不足待审）；复核动作 `accept` / `reject` / `set_representative`，复核不修改原裁决结论，另存复核记录；报告筛选按**有效结论**（有复核记录以复核为准）
- **代表值**：数值组一致时取等级最高且最新者；文本组取最高等级且最新的代表条目；复核指定主来源时以其为准
- **报告写作接入**：写作上下文仅由有效结论构成；报告 Markdown 使用脚注语法 `[^n]` + 定义区（与现有 mistune / Python-Markdown 解析兼容），数据点带上标引用；待审默认并入报告附录（可配置关闭）；产物中提供 `[序号] ↔ 证据组/条目` 映射
- **DOCX 脚注（自研注入）**：生成主体时在下游降级前截走脚注定义；保存后在 .docx（本质是 zip）注入 `word/footnotes.xml`、内容类型、关系项与正文 `w:footnoteReference`；Word 自动编号（上标数字、无方括号），同一数据多次引用时每处插入独立脚注、内容相同；脚注内容 = 标题 — 发布主体（等级）· 日期 · URL（超链接）。验收：Word 与 WPS 可见当页脚注、URL 可点击、Word 另存 PDF 后保留
- **重生成**：只重跑写作阶段（不重新检索抓取）；产出新版本文件（版本号递增），旧版本保留在 outputs，版本记录入库
- **复核后端**：FastAPI 独立页面与 JSON 接口（列待审证据组、提交复核动作），无登录（内网工具）；从研究结束事件可达。API 契约：按 research_id 列出待审组（含各来源对比数据）；提交复核动作（证据组 ID、动作、可选主来源、复核人）返回更新后的组状态
- **存储（SQLite，证据系统之记录）**：表涵盖 运行（run）、来源档案、证据条目、证据组（含裁决结论与代表值）、复核记录、裁决/归并日志；使用 `pragma user_version` 做轻量迁移；JSON + MD 产物由库导出为快照（schema_version → 2）。后端 `reports.json`（ReportStore）本期不迁移
- **WS 事件**：新增聚类/裁决进度与统计事件；研究结束的 `path` 事件增加报告版本与复核入口链接
- **配置项**（类型声明 + 默认值）：`ADJUDICATION_ENABLED`(false)、`ADJUDICATION_RULES_PATH`(空 → 包内默认)、`EVIDENCE_DB_PATH`(data/evidence.db)、`ADJUDICATION_LLM`(fast)、`ADJUDICATION_PENDING_BLOCKS_REPORT`(false)、`REPORT_PENDING_APPENDIX`(true)

### 引用 ADR

- ADR-0001 证据层顶层触发、子研究者抑制
- ADR-0002 来源等级规则即数据（本阶段的裁决策略表延续同一思路）
- ADR-0003 原文引用 fail-closed
- ADR-0004 裁决策略：确定性分块、独立来源按主体、转载保守归并、参数即数据
- ADR-0005 证据持久化：SQLite 作为证据系统之记录

## Testing Decisions

**好测试的标准**：只测外部行为，不测实现细节。以各 seam 的输入输出为断言对象；不断言内部函数调用顺序、不硬编码 prompt 全文（prompt 中的 schema 契约可用结构性断言）；测试默认离线（沿用仓库 `GPTR_BLOCK_NETWORK` 网络熔断约定），LLM 用假实现注入；DOCX 用结构化断言（解包 zip 校验脚注部件与引用），不依赖本机安装 Word。

**被测 seam（1 新增 + 3 复用）**：

- **evidence 模块公开入口（新增 seam）**：聚类与裁决管线的完整覆盖——键分块、口径拆组、指标同义归并、各级门槛、独立性（主体去重/域名兜底）、转载归并（保守）、容差比较与裁定顺序、待审判定、代表值、有效结论（复核优先）、产物 schema v2 与摘要统计
- **GPTResearcher（复用，现有最高入口）**：开关默认关闭的回归（行为零变化）；开启时顶层研究者产出裁决产物、子研究者被抑制；写作只使用有效结论、待审进附录受配置控制；重生成只重跑写作
- **后端 FastAPI 复核与重生成接口（复用）**：TestClient 断言待审列表、复核动作、审计字段（复核人/时间）、重生成触发与版本递增
- **DOCX 转换出口（复用/扩展）**：含脚注定义的 Markdown → .docx 文件；断言脚注部件存在、正文含脚注引用、脚注文本为"标题 — 发布主体（等级）· 日期 · URL"、URL 为超链接；无脚注输入的既有行为不变

**先例**：`tests/test_evidence_integration.py`（阶段一集成）、`tests/test_source_curator_json_parsing.py`（假 LLM + 脏 JSON 容错）、`tests/test_deep_research_parsing.py`（参数化约束输出）、`tests/retrievers/`（mock HTTP）、`tests/backend/`（结构性文件断言）。

**黄金用例验收**（真实查询 + 配置的检索器与 LLM）：证据组与裁决结论符合裁决策略表（抽查 ≥20 条，含至少一个跨来源一致组、一个冲突待审组）；报告正文仅含有效结论且每个数据点带上标，Word 中打开可定位当页脚注；待审默认出现在附录；在复核页面处置一个待审组后重生成，新版本报告反映处置且旧版本保留。

## Out of Scope

- PDF 与网页端脚注（PDF 另有前置：Windows 缺 GTK 库需修复或替换引擎；部署环境待确认）；交叉引用同号复用
- 已裁决结论的跨调研复用（"该指标已有 A 级数据"直接采纳）；本阶段仅做抽取缓存
- 按指标覆盖容差、按发布主体的个性化门槛（先支持等级级）
- 生成后数字级审计与幻觉门禁（后续阶段）
- 多用户、登录与权限；国际来源分级规则；`exclude` 域名；表格抓取召回改造（阶段一 backlog）
- DetailedReport 子主题来源的完整聚合（待 deep/detailed 合并后由合并编排器统一）
