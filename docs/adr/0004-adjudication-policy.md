# 裁决策略：确定性分块聚类、独立来源按主体、转载保守归并、参数即数据

- 状态：accepted
- 日期：2026-09-29

## 决策

证据组 = 实体+指标+期间+地域+单位 的确定性分块，块内经 LLM 结构化判定（指标同义归并、口径一致性）后成组，口径不同一律拆组。独立来源按**发布主体**计数（无 publisher 时退化按域名），转载在有明确来源标注或原文引用高度相似时归并为一条，判定存疑按"不算独立"处理（保守）。数值一致性用相对容差（默认 ±5%）；不一致时按等级 → 时效裁定，仍不能裁定进待审。各等级所需独立来源条数默认 A=1、B=1（可配）、C=2、D=3，与容差一起写入外部数据文件（裁决策略表），随包发布、路径可覆盖。

## 原因

领导采用报告的前提是"可信"：宁可多要来源，也不能把转载误算成交叉验证；阈值与容差必须业务可调、结果可复现，因此参数即数据（延续 ADR-0002 的思路）。确定性分块保证可解释、可复现，LLM 只承担"同义词、口径"这类无法规则化的判定，且每条判定留痕落库。

## 考虑过的方案

- **独立性只按域名**：同一发布主体的多个域名会虚增独立来源数，为转载冒名留下入口。
- **数值容差取 0**：合理的四舍五入/表述差异会被误判为冲突，抬高待审量。
- **纯 embedding 聚类**：不可解释、阈值难调，且无法表达"口径不同不合并"的业务规则。

## 后果

- 聚类依赖 LLM 判定，结论不能 100% 复现，审计依赖落库的判定记录。
- 保守的转载判定会压低"独立来源数"、抬高待审量，需要复核界面兜住。
