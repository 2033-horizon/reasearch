## 1. 目标

展示报告的证据、版本和限制，允许解释已有内容，同时阻止旧快速搜索绕过核验。

先阅读 [统一约定](./COMMON.md)、[执行总览](./README.md) 和 [PRD](../market-insight-agent-prd.md) §7.6、§7.7、§9.3。工单中的文件范围相对于仓库根目录；新增路径尚待实现。前置产物须已合入当前执行分支，不能另造占位依赖后宣称完成。

## 2. 当前代码入口

- [当前报告组件](../../../frontend/nextjs/components/ResearchBlocks/Report.tsx)
- [现有联网聊天](../../../backend/chat/chat.py)

这些文件是阅读与复用入口，不表示都必须修改。优先在本单责任范围实现，通过契约接入现有模块。

## 3. 输入与交付物

**输入**

- 已发布报告版本及冻结证据、报告质量状态，用户问题与受保护身份。

**交付物**

- 报告阅读面板、证据跳转事件、限定于报告证据的聊天子路由。

## 4. 实现范围

1. 显示摘要、数据表/图表、分析、争议/缺口及附录；保留预测/推断/建议标签和完整/部分完成状态。
2. 引用号通过证据 ID 触发侧栏，显示所读报告版本、截止日、规则版本和过时提示，不能默认把最新引用配给旧正文。
3. 追问服务从服务端加载所选报告/证据，不把客户端上传的整段 report 当作已验证事实。
4. 聊天仅解释既有证据与计算，禁用旧 quick_search 自动联网；超出对象/期间/证据范围返回需要补充研究的结构化提示。
5. 聊天中的事实回答也要引用冻结证据并检查支持性；模型输出新数字、无依据事实或校验失败时不能直接展示为可信回答。
6. 交付面板和独立聊天 router，最终页面/路由注册交 MI-023；下载按钮消费 MI-022 契约。

## 6. 验收条件

- [ ] 阅读历史报告时引用对应历史证据，修订提示不会悄悄改写正文。
- [ ] 用户问“这个增速怎么计算”可展示输入和公式；问新年份数据时不触发旧快速搜索。
- [ ] 客户端伪造 report 字段不能让后端把新内容当作已验证材料。
- [ ] 不支持的新数值不会通过聊天旁路进入界面，引用可打开同一证据侧栏。
- [ ] 跨空间报告/聊天读写被拒绝，报告待复核与部分完成状态清楚可见。

## 7. 验证与交接

- 前端类型/构建与报告交互检查；后端测试范围内解释、范围外拒绝、伪造上下文、错误引用和未授权读取。

按 [统一交接模板](./COMMON.md) 报告实际运行命令、结果、未测项、接口变化和集成说明。组件尚未挂入主应用时，明确 `ready_for_integration` 及接入工单，不将模拟结果冒充真实端到端能力。
