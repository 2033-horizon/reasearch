## 1. 目标

把已验收模块组成实际可使用的内部应用，并验证中断、预算、权限及变更不会破坏证据链。

先阅读 [统一约定](./COMMON.md)、[执行总览](./README.md) 和 [PRD](../market-insight-agent-prd.md) §7.8、§9、§10、§13 的 M5。工单中的文件范围相对于仓库根目录；新增路径尚待实现。前置产物须已合入当前执行分支，不能另造占位依赖后宣称完成。

## 3. 输入与交付物

**输入**

- 全部 P0 组件交接、真实路由/页面、运行配置；通过依赖闭包包含 MI-001–MI-022。

**交付物**

- 可运行的完整应用、部署/运行/备份恢复说明、故障和权限验证结果。

## 4. 实现范围

1. 接入证据/复核/报告页面、聊天与导出 router，核对 API 字段和事件版本；删除或禁用仅开发演示占位，保留必要 fixture 模式。
2. 从 UI 提交任务运行完整链，验证 HTML/PDF/表格和所有异常路径均走统一核验与发布门槛。
3. 在采集、核验、写作、发布阶段分别模拟连接断开与 worker 中断，检查幂等、租约、恢复和未知上游结算处理。
4. 用初始 3 并发条件验证预算隔离、事件串流、资源限制和取消；记录状态查询 P95 及流程耗时，不编造达标数据。
5. 遍历受限文件、历史版本、证据、复核、聊天、导出等访问边界；检查重定向/上传/提示注入与日志密钥泄漏。
6. 演练原文修订、局部重核验、保留期清理及备份恢复；说明如何部署、配置 provider、轮换凭据、定位失败和回滚新增模式。
7. 只修复集成暴露的必要问题；业务质量、人工时间节省和上线验收结论交 MI-024。

## 6. 验收条件

- [ ] 通过实际网页和 API 完成研究→查看证据→复核→新报告→导出的主路径，而不是各模块独立演示。
- [ ] 断线、重启、取消和预算中止不会造成已核验误标、重复证据或跨任务事件混入。
- [ ] 所有新入口和直接下载路径执行相同权限；原文/文档不能泄漏到公共目录。
- [ ] 修订后当前版本提示需重核验，历史可追溯，备份能恢复报告及其必要证据。
- [ ] 运维说明包含配置、启动、检查、备份/恢复和已知限制；性能结果注明环境和规模。

## 7. 验证与交接

- 运行完整本地集成场景、现有相关回归与前端构建；执行故障注入和权限矩阵。
- 缺少生产网络/身份环境时完成可控测试并明确未验证项，不用这些结果宣称真实线上质量已达标。

按 [统一交接模板](./COMMON.md) 报告实际运行命令、结果、未测项、接口变化和集成说明。组件尚未挂入主应用时，明确 `ready_for_integration` 及接入工单，不将模拟结果冒充真实端到端能力。

## 8. 本单边界

不在集成阶段偷偷增加 P1 功能或修改采纳阈值来绕过失败；实际生产部署须依用户部署指令。
