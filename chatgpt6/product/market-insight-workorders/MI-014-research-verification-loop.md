## 1. 目标

让系统根据缺口自动追加有针对性的研究，在预算内产出已核验资料和明确的不足清单。

先阅读 [统一约定](./COMMON.md)、[执行总览](./README.md) 和 [PRD](../market-insight-agent-prd.md) §5、§7.2、§7.4、§10。工单中的文件范围相对于仓库根目录；新增路径尚待实现。前置产物须已合入当前执行分支，不能另造占位依赖后宣称完成。

## 2. 当前代码入口

- [现有研究主流程](../../../gpt_researcher/skills/researcher.py)
- [深度研究参考](../../../gpt_researcher/skills/deep_research.py)

这些文件是阅读与复用入口，不表示都必须修改。优先在本单责任范围实现，通过契约接入现有模块。

## 3. 输入与交付物

**输入**

- 搜索规划服务、全部 P0 collector、完整 verifier、Runtime/BudgetGuard 与冻结指标实例。

**交付物**

- 可从任务 API 执行的搜索→留存→抽取→评级→核验→补搜循环，最终证据快照与覆盖/缺口结果。

## 4. 实现范围

1. 在 M1 工作流上接入分层检索、附件/表格、出处识别和交叉判定，统一记录每轮产生的资料和核验结果。
2. 根据原始出处缺失、低等级、期间缺失、独立性未知和冲突生成定向补搜请求；结果回到相同 Collector/Verifier，不直接追加自由文本。
3. 按指标×期间×区域计算已采纳覆盖；搜索结果数、重复证据与“已解释缺口”都不能计为覆盖。
4. 实现全部 PRD 停止条件和可配置上限，包括连续 2 轮没有新增有用独立证据、每主张有限补搜、调用/文档/时间预算。
5. 完成 A 级单证据所需冲突/修订检查后不再机械凑第二条；保留不支持原结论的资料。
6. 发布供分析阶段使用的版本化证据集及缺口；证据不足保留状态，不把阶段结束改写成任务完整完成。

## 6. 验收条件

- [ ] 仅有 C 转述时能补搜找到原始材料并重新评级；所有追加内容都有完整证据链。
- [ ] 重复转载不延长无限循环，预算或轮次耗尽能够结束并说明原因。
- [ ] 完整任务、可用但有缺口、无可用证据三种结果可区分。
- [ ] 包含 HTML、PDF、CSV/XLSX 的任务均经过相同判定入口，不存在附件旁路直接进报告。
- [ ] 有限制的真实任务服务已绑定到应用；单元测试之外有端到端固定 provider 场景。

## 7. 验证与交接

- 使用可控搜索结果序列测试补搜成功、连续无增量、冲突保留和预算中止；检查每次追加均产生持久记录。

按 [统一交接模板](./COMMON.md) 报告实际运行命令、结果、未测项、接口变化和集成说明。组件尚未挂入主应用时，明确 `ready_for_integration` 及接入工单，不将模拟结果冒充真实端到端能力。

## 8. 本单边界

不生成完整市场分析报告，不在 budget_exhausted 时降低采纳标准。
